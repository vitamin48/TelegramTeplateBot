# Telegram Bot Template Pro (aiogram 3)

[![Python 3.11+](https://img.shields.io/badge/python-3.11+-blue.svg)](https://www.python.org/downloads/)
[![aiogram 3](https://img.shields.io/badge/aiogram-3.x-green.svg)](https://github.com/aiogram/aiogram)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://opensource.org/licenses/MIT)

Это продвинутый и масштабируемый шаблон для создания Telegram-ботов на **aiogram 3**, основанный на лучших практиках production-ready приложений. Он предоставляет надежный фундамент для разработки сложных ботов с фоновыми задачами, гибкой архитектурой и надежным хранением данных.

> ### Ищете более простой старт?
> Этот шаблон использует PostgreSQL, Redis и Arq для максимальной производительности и надежности. Если вам нужен более легкий вариант с **SQLite** и без сложных зависимостей, переключитесь на ветку **[TemplateLight](https://github.com/vitamin48/TelegramTeplateBot/tree/TemplateLight)**.

## 🚀 Ключевые особенности

-   🐘 **PostgreSQL**: Надежная и масштабируемая база данных вместо SQLite.
-   ⚡ **Redis**: Хранение состояний FSM, что предотвращает потерю данных при перезапуске.
-   🕒 **Arq (фоновые задачи)**: Выполнение "тяжелых" операций (рассылки, генерация отчетов) в отдельном процессе, не блокируя основного бота.
-   🔑 **.env**: Безопасное хранение конфигурации и секретов.
-   🛡️ **Готовые Middlewares**: Защита от флуда (троттлинг) и удобное управление сессиями БД.
-   👑 **Гибкое управление админами**: Права хранятся в базе данных и могут меняться "на лету".
-   ✍️ **Продвинутое логирование**: Цветные логи в консоли для разработки, запись в файл и отправка критических ошибок в Telegram.
-   🏗️ **Продуманная архитектура**: Четкое разделение логики на слои (handlers, services, middlewares).

## 🏛️ Архитектура проекта

Шаблон построен на принципах разделения ответственности для удобства поддержки и масштабирования.

-   `bot.py`: Главный файл, точка входа. Инициализирует все компоненты (бот, диспетчер, пулы соединений) и запускает бота.
-   `worker.py`: Файл для запуска воркера Arq. Он выполняет фоновые задачи, определенные в `services`.
-   **`handlers/`**: Слой представления (Controllers). Здесь находятся хэндлеры, которые принимают апдейты от Telegram (`Message`, `CallbackQuery`), вызывают необходимую бизнес-логику из `services` и отправляют ответ пользователю.
-   **`services/`**: Слой бизнес-логики. Содержит основную логику вашего приложения. Функции в этом слое не зависят от `aiogram` и могут быть легко протестированы или переиспользованы.
-   **`middlewares/`**: "Промежуточное ПО". Модули, которые обрабатывают входящие апдейты до того, как они попадут в хэндлеры (например, для проверки троттлинга или создания сессии БД).
-   **`sql/`**: Содержит `.sql` файлы для инициализации схемы базы данных.

## ⚙️ Настройка и запуск

### Шаг 1: Предварительные требования

Убедитесь, что у вас установлены:
-   Python 3.11+
-   Git
-   PostgreSQL (версия 12+)
-   Redis

### Шаг 2: Установка проекта

1.  **Клонируйте репозиторий:**
    ```bash
    git clone https://github.com/vitamin48/TelegramTeplateBot.git
    cd TelegramTeplateBot
    ```

2.  **Создайте и активируйте виртуальное окружение:**
    ```bash
    python -m venv .venv
    # Для Linux / macOS:
    source .venv/bin/activate
    # Для Windows:
    .venv\Scripts\activate
    ```

3.  **Установите зависимости:**
    ```bash
    pip install -r requirements.txt
    ```

### Шаг 3: Настройка окружения

1.  **Настройте базу данных PostgreSQL:**
    -   Создайте нового пользователя и базу данных для бота.
        ```sql
        CREATE DATABASE my_bot_db;
        CREATE USER bot_user WITH PASSWORD 'your_strong_password';
        GRANT ALL PRIVILEGES ON DATABASE my_bot_db TO bot_user;
        ```
    -   Примените схему базы данных из файла `schema.sql`. Это создаст все необходимые таблицы.
        ```bash
        psql -U bot_user -d my_bot_db -f sql/schema.sql
        ```
        *(Вам может потребоваться ввести пароль пользователя `bot_user`)*

2.  **Настройте переменные окружения:**
    -   Скопируйте файл `.env.example` в новый файл с именем `.env`.
        ```bash
        cp .env.example .env
        ```
    -   Откройте файл `.env` и заполните его вашими данными:
        -   `BOT_TOKEN`: Токен вашего бота от [@BotFather](https://t.me/BotFather).
        -   `LOGS_CHAT_ID`: ID чата/канала, куда будут отправляться логи и ошибки.
        -   Данные для подключения к **PostgreSQL** (`PG_USER`, `PG_PASSWORD`, `PG_DATABASE` и т.д.).
        -   Данные для подключения к **Redis** (`REDIS_HOST`, `REDIS_PORT`).

### Шаг 4: Запуск

Для работы бота необходимо запустить два процесса в **разных** терминалах.

1.  **Запустите воркер фоновых задач:**
    Этот процесс будет слушать очередь задач в Redis и выполнять их.
    ```bash
    arq worker.WorkerSettings
    ```

2.  **Запустите бота:**
    Этот процесс будет обрабатывать входящие сообщения от пользователей.
    ```bash
    python bot.py
    ```

**Поздравляем! Ваш бот запущен и готов к работе.**

## ✨ Что включено в шаблон?

-   **Команда `/start`**: Регистрирует нового пользователя в базе.
-   **Команда `/help`**: Отправляет справочное сообщение (текст берется из БД).
-   **Команда `/broadcast` (только для админов)**: Запускает FSM для создания и отправки рассылки всем пользователям бота.
-   **Команда `/report`**: Демонстрация постановки "тяжелой" задачи в очередь `arq` и ее выполнения в фоновом режиме.
-   **Универсальный хэндлер**: Пересылает все текстовые сообщения от пользователей в лог-чат для мониторинга.
-   **Обработчик ошибок**: Ловит все исключения, отправляя подробный отчет в лог-чат, не давая боту "упасть".
